# 当前 3D IC 全局布线算法：从赛题到实现

更新：2026-11-05。本文以本工作树 `codex/fixed-resource-handoff-20261105` 的源码和脚本为准，面向已经读过赛题、但尚未读过路由器代码的读者。先理解模型，再沿一次运行的顺序阅读。本文的“当前”指代码能力与入口设置；已有 Guide 的成绩、尚未验证的代码包和比赛最终成绩分开说明。

## 1. 程序到底要做什么

DEF 给出芯片外形、GCell 网格、轨道、器件位置和需要连接的网络；LEF 给出金属层方向以及器件 PIN/OBS 的真实几何；热 JSON 给出每个位置的温度。程序不能移动器件或改输入，只能为每个真实网络输出一组 `x1 y1 x2 y2 metalN` 矩形，称为 Guide。Guide 是全局布线指示区域，不是每根详细金属线。

一条网络可能有多个 PIN。所有 PIN 必须接到同一个连续的 Guide 结构，并且接入 PIN 的**实际层**。下 Die 使用 M1–M10，上 Die 使用 M11–M20。跨 Die 网络必须在 M10/M11 之间用一个实际 TSV 连接；同 Die 网络不能借另一个 Die 绕路。普通换层是相邻金属层之间的 via。Guide 要符合层首选方向、GCell 边界、DIEAREA、PIN 接入和障碍约束。最终导出必须保留所有真实网络。

可以把问题想成三维网格上的带资源限制的多终端接树：每个网络要连通，但网络之间争夺同一 GCell 的可用轨道；跨 Die 网络还要争夺合适的 TSV 落点。温度影响 TSV 放在哪里更有利，不能代替连通性或合法性。

## 2. 两个容易混淆的“网格”

**搜索图**：`src/router/routing_graph.*` 把每个 `(列, 行, 金属层)` 变成节点。层首选方向上的相邻节点有平面边；允许的相邻层节点有 via 边。搜索会询问边是否可走、长度和当前代价。图上的物理边使用量有助于布线路径搜索。

**Guide 资源账本**：评分关注最终矩形覆盖了哪些 GCell、每格有多少轨道容量和多少固定/可移动需求。固定需求来自 PIN/OBS，容量来自 **DEF TRACKS**，而不是拿 LEF PITCH 代替。普通 Guide、via 重叠和 TSV 按各自规则计入。搜索图里“只走过一条边”不保证导出的整个矩形只占一个资源单位；因此程序在候选编码后还要按实际 Guide 重新计量。`src/objectives/net_cell_contribution.hpp` 统一逐网逐层逐格的贡献，`src/objectives/official_metrics.*` 汇总全局指标。

例如某格容量 4、固定需求 2、已有路线需求 1，新路线再占 2，则总需求 5、溢出 1。若在搜索时只看新路线长度，会选中这个拥塞格；拥塞价格让搜索权衡一次绕行。正式 Q 还会考虑容量归一化并对格子求平方和，所以“减少一个溢出格”和“把已有严重拥塞继续加重”效果不同。零容量格另有保守处理，不能按普通分母计算。

TSV 在 M10/M11 两层的需求由其 5×5 μm 几何与实际轨道覆盖确定。同一网络的 TSV 与表示它的 Guide 在落点处合并计数，不重复加；不同网络即使落在同格，也分别贡献需求。当前生产合法掩码只检查 **M10/M11** 的 PIN/OBS；这是官方答疑和 001/003 已返回 PASS 的口径。TSV 仍须是合法的真实位置，不能靠 Guide 截断或计量漏洞制造收益。

## 3. 程序比较什么分数

本项目读回模型把单例质量拆成线长 W、拥塞 C、热 T，并计算 `S = 0.45 W + 0.30 C + 0.25 T`，各分项以 0–100 表示；源码里的 `quality` 是除以 100 后的数。若实测线长为 L、参考线长为 R，则当前线长分 `W = 100 × min(1, R/L)`。拥塞用各格归一化溢出平方和 Q，`C = 100 / sqrt(1+Q)`。热分使用 TSV 逐格数量与温升的 Pearson 相关系数 rho，`T = 100 × (0.5 + 0.5 tanh(G × rho))`；G 是热增益。TSV 数量不是简单的“有/无”位图，同格多个 TSV 会改变相关系数。

上面是**单例质量读回**，不是比赛最终聚合公式。平台还有合法性、运行效率以及公开/隐藏例的聚合。已知公开例 G 在研究入口显式传入；平台代码包不提供逐例 G，程序用 hottest-K 上界估计，不能按输入文件名查表。隐藏例 G 和最终排名均不能由公开例读回推断。

还要分清三层评价：

1. **路径搜索价**：长度、via、预计新增拥塞和历史拥塞价格的加权和，用来快速生成备选路径。
2. **内部候选验收**：把候选编码为 Guide 后重新计量，在当前配置的目标下决定接受或回滚。候选入口的 `--congestion-target-q 30` 在 Q 高于 30 时，对 C 使用 Q=30 处的切线延拓，避免在高拥塞区梯度过小；这是搜索与内部验收的优化代理。
3. **实际读回分数**：`eda_measure_documented` 和平台返回仍用原来的 `100/sqrt(1+Q)`，不会因为设了目标 Q=30 就把高 Q 成绩提高。离线模型结果也不等于官方重新评测。

因此，算法并不是在一次 Dijkstra 中直接求出全局最高 S。它先用便宜的局部代价提出候选，再用完整 Guide 的计量与校验作最终筛选；这种局部搜索仍可能停在局部最优。

## 4. 启动：解析、建图、准备 TSV

`src/main.cpp` 解析参数并选择配置；`src/parser/` 读取 DEF/LEF/thermal。解析要正确处理实例翻转/旋转、一个 PIN 的多个 RECT、IO PIN 和真实层。随后建立 RoutingGraph：记录可走节点/边、每层容量、固定 PIN/OBS 需求、PIN 可接入区域、TSV 可用掩码和热图。每个网络的参考线长也在此阶段准备；参考量不能通过虚增 Guide 矩形来操纵。

跨 Die 网络先由 `src/router/tsv_policy.*` 分配 M10/M11 落点。对每网候选落点，算法估计上下两边的接线代价、资源和热影响，再用带容量的最小费用匹配寻找整体可行分配；源码使用残量图和最短增广路。这样比每条网各自抢当前最近的格子更能避免早期分配把后续网络逼到坏位置。已经有固定接口 PIN 的网络受到相应几何限制。默认落点政策是一格一个 TSV；预布线共享 hub 和自动选择是另外的实验能力，当前代码包入口未启用。

候选入口还可开启 `future_tsv_reservation`：尚未开始布线的跨 Die 网，其已选 TSV 在 M10/M11 的**必要需求**先临时加入搜索价格，防止先布的普通路线占满未来必需的落点。轮到该网时，先撤销这份“承诺”，再布真实路线并把真实需求记入账本。初始路由结束后，程序检查所有预留已清零。预留只影响搜索和拥塞预估，不是额外的正式 TSV。

## 5. 初始布线：为每网接一棵树

`src/router/negotiated_router.cpp` 的 `route_all()` 当前先排跨 Die 网络，再按 PIN 数、PIN 包围盒半周长 HPWL、网名稳定排序。这个顺序是启发式，并不根据输入文件名选择策略。此前尝试过按出线难度排序，三公开例单次对照差异处于波动范围，相关开关已撤销。

每个网络先得到一组可接入终端：真实 PIN 的合法接入点，以及跨 Die 网已分配的 TSV。`build_route()` 调用树构建过程，把尚未连上的终端逐步连接到已有树。路径搜索使用 A*/Dijkstra 及大规模设计的有限预算快速候选；已有本网络树边可复用，从而避免把一棵树拆成彼此独立的点对连线。边价主要包含：平面距离、换层 via 成本、进入该格预计新增拥塞、历史拥塞价格。PIN 接入有本网络的合法抵扣，不能把别网或整层的占用都视为免费。构树和局部替代候选在 `negotiated_router.cpp`，PIN/TSV 接入辅助在 `pin_local_router.cpp`、`tsv_local_router.cpp`。

一个简化例子：M3 上两个 PIN 在同一行，直连只需 5 格，但中间一格已满；绕到邻行需要 7 格和两个转弯。若直连使 Q 明显上升，搜索价可能选 7 格路线；若邻行也拥塞，仍可能选直连。这个判断依赖当前全部已布网络，因此布线顺序会影响初始答案，后续 RRR 才有机会修正。

### 为什么要“爬层前先横走”

003 曾出现大量从 PIN 所在列直接竖直换层、穿越预先已满 GCell 的情况。`src/router/climb_escape.cpp` 的 `--climb-escape-radius 3` 在检测到终端上方柱子拥塞时，搜索终端周围有限窗口内的可达出口，估算“先横走到出口、再爬层、再去目标”的总代价。窗口使用实际边价，并只在同 Die 允许层内搜索；若直爬更合适，仍可选原路。出口可能仍在终端原列：路径先退到旁边一列爬过满格，再回到原列上层，这同样算横走，判断看路径而不是出口坐标。它是候选生成方法，不保证每次减少拥塞。半径 0 关闭，8 的已测结果并未胜过 3。当前官方模式在规定 profile 下默认 3，代码包入口也显式传 3。

每网路径会被 `encode()` 转换成真正的 Guide 矩形，并检查 GCell 对齐、层方向、PIN 覆盖、连通和 TSV 映射。编码后的矩形资源与线长才写入账本。所有网完成后，进行一次全量校验和计量，得到可保留的初始解。

## 6. 迭代修复：为什么要拆线再布

初始逐网构树只看当时状态；早布的网可能占据后来更重要的通道。Rip-up and Reroute（RRR）选出拥塞相关网络，撤掉其可移动贡献，在其他网络仍占用的状态下重布，再比较新旧完整方案。`src/router/hotspot_rrr_router.cpp` 可按格子热点及“能被重布移走多少需求”给候选排序；固定 PIN、固定 TSV 等不可移贡献不会冒充可消除拥塞。`negotiated_router.cpp` 中的历史价格增加反复拥塞区域的搜索成本，避免网络在几轮中来回抢同一位置。

RRR 以有界网数、组大小、轮数和时间运行。每组包含路线、资源 owner 和分数账本的事务；候选无效、超时或质量下降要回滚。回滚后再全量校验，不能把半更新状态导出。当前候选/包入口将 RRR 轮数设为 64、网数上限增大，并在自适应调度中预留最多 2000 秒。`rrr_reserved_seconds` 是总时限内的一段预算，不是额外加时。官方模式最后留 800 秒做溢出清理：还压在超容量格子里的线网逐根重布，单根绕不出去时连同周围满格里的线网一起重布，按完整分数验收（D-017）。

初始 RRR 后可尝试：

- **动态 TSV**：`dynamic_tsv_router.cpp` 把跨 Die 网移到另一个合法落点，重连受影响网络，比较热、拥塞与线长的总变化。落点报价只考虑必要 TSV 的一部分影响，最终仍需完整重连计量。
- **TSV 归属重匹配**：`tsv_rematch_router.cpp` 在现有落点之间交换网络归属，尝试改善总体路线。多网同格时相关动态阶段会跳过，因为当前索引/事务主要按单 owner 设计。
- **线长恢复**：`budgeted_recovery_router.cpp` 在剩余预算内试局部重连和候选筛选，降低线长而不盲目牺牲拥塞、热或合法性。

`adaptive_schedule.cpp` 在启用时把 RRR、TSV、重匹配和恢复分成有限时间片：每类先试一轮，之后根据实际收益/耗时分配下一片；连续无收益就停。具体阶段由脚本中的 preset 与显式参数决定。`via-stack-radius` 和 `recovery-global-wirelength` 当前关闭。已有预布线同格 TSV 实验，但**通用的多 owner 动态 TSV 搜索还未实现**，不能通过删除唯一性检查来假装支持。

## 7. 导出和核验：什么叫“得到一个结果”

最终 `route_all()` 再做全量合法性检查和计量；`export_guide()` 按网络写矩形，随后**重新读取磁盘上的实际文本**，复查 GCell 编码、网络和 PIN/连通等条件。这一步防止内存状态正确而序列化后格式或几何错误。独立命令 `eda_validate_guide` 检查已导出的 Guide；`eda_measure_documented` 从原始输入和 Guide 重新算 L、reference、Q、rho、W/C/T/S、via/TSV 等。读回与路由器共享一些代码，因此“自家 PASS”不能替代平台合法性和评分。

研究记录还应保留输入、二进制、Guide 和规则版本/哈希、G、预算、实际墙钟、峰值内存、逐例合法性与分项。Guide-only 快评跳过路由，返回的 0 秒不能当作路由速度。平台封装的部分成功均分也不能当三公开例或六例最终成绩。

## 8. 当前三个入口怎么选

| 入口 | 资源/热设定 | 主要目的 |
| --- | --- | --- |
| `scripts/run_current.sh` | 必须显式传 `--thermal-gain G`；固定资源默认 `production` | 按已文档化规则做可控研究/对照；A150、documented、site-20261029，TSV 禁放只看 M10/M11 |
| `scripts/run_fixed_resource_candidate.sh` | 显式 G；`observed-20261104` | 研究候选；Q 目标 30、未来 TSV 预留、64 轮 RRR、半径 3、结尾溢出清理 800 秒（连同挡路线网），默认 3600 秒 |
| `scripts/run_package.sh` | 平台不传 G，使用 hottest-K 估计；`observed-20261104` | 代码包入口；其他关键设置与候选入口对应，半径 3 和清理 800 秒显式传入；包内 `run.sh` 设 3600 秒 |

`production` 固定资源账本保留官方文字规则；`observed-20261104` 来自四份平台样本的几何反推及后续三份 Guide 的逐格验证。它仍与 A148 上边界文字有冲突，零容量、全部非溢出格和隐藏例没有得到同等验证。两种模型的离线分数应分开报告；详见 [固定资源模型](rules/fixed-resource-model-20261105.md)。入口后置选项可覆盖部分设置，实验必须记录最终 argv。`run_current.sh` 的已知 G 与包入口的 G 估计不同，即使路线设置相同也不保证同分。

## 9. 已知成果和未解决问题
